# Changelog

Every change names the failure it prevents — a change that cannot is ceremony.
Versions follow semver (`major.minor.patch`): major for breaking changes, minor
for backward-compatible additions, patch for fixes and documentation-only edits.

## 1.0.0 — 2026-05-31

The first release: the nine skills across three work stances, the deterministic
shell, and the claims/conflicts machinery that make the template what it is.

### Mental model

- **Checks are classified as `contract` or `probe`.**
  A contract is an algorithmic promise: red means the *code* is wrong and `build`
  halts. A probe is a theoretical expectation: red means the *belief* may be
  wrong and a conflict opens. Names that describe the distinction directly.
- **Three stances named for what they do — `think` / `build` / `write`.**
  Being wrong is cheap in `think` and `write`;
  `build` is the one expensive mode and the only stance that halts. There is no
  skill literally named `write`.
- **Disagreements are first-class — `conflicts/`.** One file per dispute, with its
  own schema; a conflict is a boundary disagreement (a belief vs. the code), and
  `make status` lists every open one.
- **Disputedness is derived, never stored.** Whether a claim is contested is a
  join over the open-conflict register, not a status field someone must remember
  to flip.
- **One source of truth for behaviour.** `skills/*/SKILL.md` is canonical and
  committed; the per-tool adapters (`.claude/`, `.opencode/`, `.agents/`) are
  generated by `make sync` and git-ignored, so a never-committed file cannot
  drift in history.

### Skills — the canonical nine

Grouped by stance:

- **think** — `/start` (session opener, cold-open recovery), `/think` (cheap
  exploration; the one path that adjudicates a `conflicts/` file), `/pin`
  (promote a hardened note into a load-bearing claim, with checks and registered
  vocabulary), `/log` (session closer, appends to `JOURNAL.md`).
- **build** — `/build` (spec → one RED test per check → `src/` until the contract
  checks pass; the suite's only halt), `/critique` (adversarial read of a single
  artifact; chat-only, writes nothing).
- **write** — `/draft` (settled claims and their figures into paper prose),
  `/brief` (a digest or handoff generated from committed state), `/intake` (land
  outside material with provenance, quarantined until deliberately promoted).

Vocabulary is registered at `pin` time, so there is no separate define step.
`figure`, `recall`, and `spike` are folded or deferred — they are not skills in
1.0.0 (see GUIDE.md §13 for why each is held back).

### New mechanisms

- **The deterministic shell mints; the model reads.** The `Makefile` and
  `scripts/` are the only things that mint timestamps, ids, and commits — never a
  test runner, linter, or compiler called directly. Read `make now` for the clock
  and `make new-claim` for ids.
- **One disagreement lifecycle:** `make open-conflict → /think → make
  close-conflict`. `make status` and `/start` read the same open-conflict list,
  so nothing depends on a human remembering a dispute exists.
- **The one guardrail.** When a contract check is still red after one honest fix
  cycle, `build` stops the line, opens a conflict, and hands the decision back —
  it never forces the test green or edits the test to pass. This is the only halt
  in the suite, stated once in `AGENTS.md`.
- **`make rename old=X new=Y`** — atomic, word-boundary cross-file identifier
  rename across `src/` and `tests/`, routing belief-side drift into the conflict
  lifecycle rather than a silent rewrite.
- **`make archive file=…`** — soft-archive any file by moving it under
  `<parent>/archived/`; `make status` excludes archived files.
- **`make validate`** — aggregate gate (test + lint + every `validate-*.sh`),
  discovered by glob and run independently so one failure never masks the next.
- **`make migrate from=<major>`** — chain-walking migration infrastructure for
  future majors (empty in 1.0.0).
- **Closed twelve-scope commit vocabulary** so the git log is itself queryable:
  `claim: conflict: src: test: spec: paper: note: brief: intake: archive:
  template: log:`.

### Versioning, migrations, and CI

- `VERSION` at repo root: `1.0.0`. Standard semver.
- `migrations/` holds one script per breaking transition (`1-to-2.sh`, …),
  walked by `make migrate from=<major>`. Idempotent, with a `dry_run=1` preview.
  Empty until the first breaking change ships with 2.0.0.
- CI (`.github/workflows/test.yml`) resolves `LANGUAGE` from `.env` then the
  committed `.env.example` (the default CI sees, since `.env` is git-ignored) and
  runs the full `make validate` — the template validated against itself on every push.

### Deferred

- `/recall` (on-demand scoped query) and trajectory-aware output.
- `/critique` note and positioning persona sets.
- Auto-firing a conflict from a structured test report (probe-red is a
  skill-procedure obligation in 1.0.0, not a shell gate).
